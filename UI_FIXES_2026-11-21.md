# Akaora Meet — visual stability fixes (21 November 2026)

This package is based on **AkaoraMeet_LiquidGlass_Menu_Clean_Localhost**, so the earlier Firebase/WebRTC, screen-share and branding code remains in place.

## Changes

- Resolved overlapping dark/light-mode CSS rules for meeting-header actions. Theme, copy-code and share-link buttons now have readable text/icons regardless of the selected site theme.
- Improved room-code, hosting metadata and clock contrast, with compact responsive header layout.
- Rebuilt the presentation-audio toggle dimensions: track and thumb stay aligned in both states. When someone else is presenting or no screen-audio track is present, the control becomes a status-only disabled control (rather than misleadingly interactive).
- Presentation controls wrap without clipping on mobile; screen share remains the main video surface while participant thumbnails stay visible.
- Added a **Fit / Fill** button inside the screen-sharing surface. `Fit` displays the whole source without cropping; `Fill` zooms to the available area and may crop edges. This preference resets when sharing ends. It only adjusts local rendering, not the WebRTC media sent.
- Reduced excessive vertical whitespace at the top of the homepage on desktop.
- Kept the Akaora Technologies navy/orange dark liquid-glass branding, SVG icons and card-free editorial sections.

## Tests and limitations

- `app.js` JavaScript syntax and referenced local assets validated.
- Headless Chromium layout measured for desktop (1778px) and mobile (390px). Presentation thumb stays inside its track, and responsive meeting header elements remain inside the viewport.
- Chromium verified the **Fit/Fill** button toggles its CSS state via the actual application event handler and that header button text remains readable when site theme is switched.
- These are interface tests; live two-device Firebase/WebRTC call performance was not retested.

## Local testing

Double-click `start website.bat` (Windows with Python 3 installed), then open `http://localhost:4173/`. Stop any old local server first and hard-refresh the browser (Ctrl+Shift+R).
